## Writing rule

For each case study, keep four things distinct: (1) the evidenced problem, (2) the author's documented motive or an explicit “not recorded”, (3) the alternative that already fits, and (4) the narrow remaining reason to build. Never convert an inference into autobiographical fact. If an existing option looks adequate, say so plainly.

## Research limits

- Checked official product documentation or product-owned pages on 16 Nov 2026. This is a capability check, not a complete market survey, price comparison, endorsement, or security audit.
- Software Inc Multiplayer (SIMM) is a third-party project on the same game; overlap warrants a direct code/compatibility comparison before asserting a unique feature.
- Tiskov source repository and Discord bot source were unavailable in the research checkouts; catalog-level statements stay marked as such.
- Private repo dirty changes were excluded. Project evidence and product availability can change after this date.
